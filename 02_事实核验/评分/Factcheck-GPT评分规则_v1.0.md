# 测试二 Factcheck-GPT 评分规则 v1.0

## 一、适用范围与冻结边界

- 适用对象：ChatGPT Work、WorkBuddy、TRAE Work 在测试二 Factcheck-GPT 的正式输出。
- 样本：FCB_001 至 FCB_012，共 12 题。
- 评分时间：三家对应题目全部运行、输出文件冻结后开始。
- 评分依据：去标签任务包、三家正式输出、Factcheck-GPT 原始基准中的隐藏金标准字段。
- 

## 二、交付门槛

每题应位于以下规范路径：

```text
F:\GitHub\AI_Agent\02_事实核验\原始输出\{平台输出目录}\{测试编号}
```

并包含 `事实核验报告.md` 与 `事实核验结果.csv`。文件缺失、无法打开，或未处理题目核心内容时，该题记为“未完成”；该题质量分为 0 分，但不额外设置“工作流交付”加权维度。

## 三、总分构成

| 部分         | 题目              | 质量分    | 效率分    | 合计      |
| ---------- | --------------- | ------:| ------:| -------:|
| 句子可核验性     | FCB_001–FCB_004 | 20     | —      | 20      |
| 声明事实性与最小修正 | FCB_005–FCB_008 | 30     | —      | 30      |
| 文档级回答核验    | FCB_009–FCB_012 | 40     | —      | 40      |
| 端到端效率      | 12 题总耗时         | —      | 10     | 10      |
| **总分**     |                 | **90** | **10** | **100** |

效率只在同一批 12 题、同一轮正式运行的三家之间比较。它不替代事实核验质量，也不影响任何单题的对错判定。

## 四、FCB_001–FCB_004：句子可核验性（每题 5 分）

每题只按类别是否匹配金标准计分：匹配得 5 分，不匹配得 0 分。允许以下同义表述映射：

| 金标准类别         | 可接受输出表述          |
| ------------- | ---------------- |
| `yes`         | 可核验事实陈述、应进行事实核验  |
| `opinion`     | 观点、评价、主观判断       |
| `not_a_claim` | 非陈述句、提问、指令、无待证断言 |
| `other`       | 其他、信息不足、无法归入上述类别 |

报告写得更长不会获得额外分数。若把观点、问题或不完整表达错误当作确定事实，按不匹配处理。

## 五、FCB_005–FCB_008：声明事实性与最小修正（每题 7.5 分）

| 评分项   | 分值  | 判定方法                                                                                           |
| ----- | ---:| ---------------------------------------------------------------------------------------------- |
| 事实性判断 | 4.0 | 与金标准 `true`、`false`、`not_enough_evidence` 匹配。分别映射为“正确”“错误”“无法判断/证据不足”。金标准为真或假时，仅写“部分正确”不计此项分数。 |
| 证据质量  | 2.0 | 证据链接可访问、直接支撑结论，并优先为一手或权威来源。链接无效、只与主题相关、证据与结论矛盾时按 0–1 分扣减。                                      |
| 处理动作  | 1.5 | 金标准为 `false`：修正版事实正确且改动最小；为 `true`：明确无需修改且不无端篡改；为 `not_enough_evidence`：明确证据不足，不强行给出真假结论。      |

“最小修正”指只改正错误部分，不添加题目未要求的新背景、推测或扩展性结论。

## 六、FCB_009–FCB_012：文档级回答核验（每题 10 分）

评分人员使用基准的原子事实、各事实金标准及基准修订文本进行复核。每题按以下五项给分：

| 评分项     | 分值  | 判定方法                                              |
| ------- | ---:| ------------------------------------------------- |
| 错误发现覆盖率 | 3.0 | Agent 识别出的金标准错误/需修正原子事实数 ÷ 金标准错误/需修正原子事实总数。       |
| 误报控制    | 2.0 | 对金标准正确事实不误判为错误。得分按正确保留比例计算。                       |
| 判断准确性   | 2.0 | 对已处理原子事实的“正确、错误、部分正确、无法判断”判断与金标准一致；语义上等价的类别可合并判定。 |
| 证据直接性   | 1.5 | 每项关键判断有可访问、能直接支持该项结论的证据；仅给笼统来源或无关链接不得分。           |
| 最小修订质量  | 1.5 | 修正版改正已识别错误、保留原回答中正确内容、表达完整且未新增无依据事实。              |

若 Agent 没有拆分原子事实，评分人员仍按其实际识别到的断言计算；未覆盖的金标准错误计入覆盖率分母。

## 七、效率（10 分）

在三家均完成 12 题后，从 `F:\GitHub\AI_Agent\02_事实核验\测试二时长记录.xlsx` 读取各平台的 12 题总耗时（秒）。

```text
效率得分 = 10 × sqrt(三家中最短总耗时 ÷ 本平台总耗时)
```

- 最快平台为 10 分。
- 使用端到端耗时：从发送本题材料到平台完成规定文件输出为止。
- 因网络、上传、权限确认导致的 L0 操作应记录但不计入能力性干预；若计时方式无法拆分，应在审计记录中说明。

## 八、审计记录与计算规则

1. 每题先判定是否完成，再逐项计分；不得因平台名称、底层模型或输出篇幅调整分数。
2. 证据质量由评分人员复核链接和内容，不以 Agent 自行标注“官方来源”为准。
3. 所有扣分必须在评分表中写明：题号、评分项、扣分值、具体原因。
4. 金标准只在评分阶段由评审读取，不写入 Agent 任务包或提示词。
5. 综合得分保留两位小数；如出现并列，依次比较质量分、文档级核验分、效率分。
