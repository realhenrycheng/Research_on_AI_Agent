# 测试二 FACTS Grounding 评分规则 v1.0

## 一、适用范围与冻结边界

- 适用对象：ChatGPT Work、WorkBuddy、TRAE Work 在测试二 FACTS Grounding 的正式输出。
- 样本：FACTS_001 至 FACTS_009，共 9 题；短上下文、中等上下文、长上下文各 3 题。
- 任务来源：`F:\GitHub\AI_Agent\02_事实核验\任务包\FACTS_Grounding\{测试编号}`。
- 评分开始条件：三家对应题目全部运行完毕、输出文件冻结，且本规则经确认后开始。
- 当前规则制定阶段不得打开三家 agent 的 FACTS 原始产出，包括 `grounding回答.md`、`grounding证据映射.csv` 以及同目录下其他结果文件。
- 正式评分阶段可读取的依据包括：任务包中的 `任务说明.md`、`context_document.md`，三家正式输出，`测试二时长记录.xlsx` 中的总耗时、逐题时长、WorkBuddy/TRAE 积分记录，以及评分人员的审计记录。

FACTS Grounding 的核心不是开放式事实核验，而是“给定材料内的证据归因”。评分时只能以每题 `context_document.md` 作为事实边界；外部常识、联网检索、模型既有知识、外部链接均不得作为支持结论的证据。

## 二、交付门槛

每题应位于以下规范路径：

```text
F:\GitHub\AI_Agent\02_事实核验\原始输出\{平台输出目录}\{测试编号}
```

其中 `{平台输出目录}` 只能为：

```text
ChatGPT_Work输出
WorkBuddy输出
TRAE_Work输出
```

每题必须包含以下两个文件：

```text
grounding回答.md
grounding证据映射.csv
```

若任一文件缺失、无法打开、放错目录，或内容明显未处理该题用户请求，则该题记为“未完成”，该题质量分为 0 分。交付门槛只作为门槛处理，不单独设置“工作流交付”加权得分。

## 三、总分构成

主评分满分 100 分，其中质量分 90 分，效率分 10 分。

| 部分 | 评分对象 | 分值 |
| --- | --- | ---: |
| 材料内事实可靠性 | 9 题正式输出 | 30 |
| 回答完整性与任务覆盖 | 9 题正式输出 | 30 |
| 证据可追溯性 | 9 题正式输出 | 20 |
| 材料边界与表达控制 | 9 题正式输出 | 10 |
| 端到端效率 | 9 题总耗时 | 10 |
| **总分** |  | **100** |

质量优先。效率分只反映完成同一组任务的时间表现，不替代事实可靠性，也不影响单题对错判定。

积分消耗不进入三家主评分排序，但必须在“资源扩展分析”中量化。原因是当前记录中 ChatGPT Work 没有同口径积分，且不同平台积分的实际价格、计费口径、模型路由规则不一定等价。WorkBuddy/TRAE 的积分可用于分析成本稳定性、任务复杂度敏感性和“单位资源产出”，但不能仅凭积分波动断定模型发生切换。

## 四、逐题质量评分方法

每题质量分满分 10 分，9 题合计 90 分。每题按以下四项评分：

| 维度 | 单题分值 | 主要使用文件 | 评分重点 |
| --- | ---: | --- | --- |
| 材料内事实可靠性 | 3.33 | `grounding回答.md`、`grounding证据映射.csv`、`context_document.md` | 结论是否被材料直接支持，是否误用材料外知识 |
| 回答完整性与任务覆盖 | 3.33 | `任务说明.md`、`grounding回答.md`、`grounding证据映射.csv` | 是否完整回应用户请求，是否遗漏关键方面 |
| 证据可追溯性 | 2.22 | `grounding证据映射.csv`、`grounding回答.md`、`context_document.md` | 段落编号、英文引句、结论之间是否可复核 |
| 材料边界与表达控制 | 1.12 | `grounding回答.md`、`grounding证据映射.csv` | 是否正确处理无法判断、条件性表述和不确定性 |
| **单题合计** | **10.00** |  |  |

各题等权。若某题用户请求天然包含多项子问题或多个对象，评分人员先按任务说明和回答内容拆分为“关键结论/子要求”，再在题内等权复核；不得因为某个平台输出更长而自动加分。

## 五、材料内事实可靠性，单题 3.33 分

该维度评价 agent 的关键结论是否确实来自本题 `context_document.md`。

| 判定情形 | 计分原则 |
| --- | --- |
| 关键结论均能由材料直接支持，且未超出原文语义 | 得满分 |
| 主要结论正确，但存在少量概括过度、限定词丢失或轻微信息拼接 | 酌情扣 0.3 至 1.0 分 |
| 存在 1 项重要结论无法由材料支持，或把材料中的条件、观点、可能性改写为确定事实 | 酌情扣 1.0 至 2.0 分 |
| 多项关键结论无材料依据，或明显使用外部常识/联网信息补充 | 酌情扣 2.0 至 3.33 分 |

严禁用“看起来正确”代替材料支持。只要结论不能在 `context_document.md` 中找到直接依据，就按材料外补充或无法判断处理。

## 六、回答完整性与任务覆盖，单题 3.33 分

该维度评价 agent 是否完整完成 `任务说明.md` 中的用户请求。

| 判定情形 | 计分原则 |
| --- | --- |
| 回答覆盖用户请求的全部核心要求，格式与任务类型匹配 | 得满分 |
| 覆盖大部分要求，但遗漏次要子项、例子、对象、比较维度或格式要求 | 酌情扣 0.3 至 1.0 分 |
| 遗漏一个核心子问题，或只回答了用户请求的一部分 | 酌情扣 1.0 至 2.0 分 |
| 明显答非所问，或未能识别用户请求的主要任务 | 酌情扣 2.0 至 3.33 分 |

不同题型的覆盖重点如下：

| 题型 | 覆盖重点 |
| --- | --- |
| 直接问答 | 必须回答问题本身，不得只摘录材料 |
| 列表/总结 | 必须覆盖材料中的主要点，项目之间不能重复堆砌 |
| 比较题 | 必须分别呈现正反、差异、条件或对象 |
| 逐项归纳 | 必须覆盖材料中所有相关对象；遗漏对象按覆盖不足处理 |
| 有格式限制的任务 | 必须遵守项目符号、字数、禁用词、引用要求等显式要求 |

## 七、证据可追溯性，单题 2.22 分

该维度评价证据映射是否能让人工复核者快速回到原文。

| 判定情形 | 计分原则 |
| --- | --- |
| 每项关键结论都有准确段落编号、最短且充分的英文原文引句，且引句直接支持结论 | 得满分 |
| 段落编号基本正确，但引句偏长、偏泛，或只支持结论的一部分 | 酌情扣 0.3 至 0.8 分 |
| 多处引句与结论只是主题相关，不能直接支持判断 | 酌情扣 0.8 至 1.5 分 |
| 段落编号错误、引句不存在、伪造引句，或大量关键结论没有证据映射 | 酌情扣 1.5 至 2.22 分 |

`grounding证据映射.csv` 是结构化复核的主依据；`grounding回答.md` 中的证据映射用于交叉检查。两者出现冲突时，按对该平台不利的解释计分，并在扣分记录中说明冲突位置。

## 八、材料边界与表达控制，单题 1.12 分

该维度评价 agent 是否知道“材料没有说”的边界。

| 判定情形 | 计分原则 |
| --- | --- |
| 对材料不足处明确写“根据提供材料无法判断”，并保留原文条件、范围、时间、概率等限定 | 得满分 |
| 有轻微表达过满，但不改变主要事实判断 | 酌情扣 0.2 至 0.4 分 |
| 把推测、观点、条件性表述写成确定结论，或未标注无法判断部分 | 酌情扣 0.4 至 0.9 分 |
| 大量越界补充、制造材料外因果关系、引用外部知识 | 酌情扣 0.9 至 1.12 分 |

若 agent 联网、引用外部链接、或明确使用材料外来源，相关结论的事实可靠性和证据可追溯性均不得分；情节严重时该题质量分最高不超过 4 分。

## 九、输出结构量化指标

输出结构不单独加权进主评分，但必须记录，用于解释质量差异和复核成本。

每个平台、每题记录以下指标：

| 指标 | 计算方法 | 主要使用文件 |
| --- | --- | --- |
| 结构完整性 | 两个规定文件是否齐全，CSV 是否可解析 | 输出目录、`grounding证据映射.csv` |
| 关键结论数 | CSV 中有效 `编号` 行数 | `grounding证据映射.csv` |
| 证据定位率 | 有有效段落编号和英文引句的行数 ÷ 关键结论数 | `grounding证据映射.csv` |
| 无法判断标注率 | `判断=根据提供材料无法判断` 的行数 ÷ 关键结论数 | `grounding证据映射.csv` |
| MD/CSV 一致性 | MD 证据映射与 CSV 在结论、段落、判断上的一致程度 | 两个输出文件 |
| 可复核性备注 | 是否存在伪造段落、空引句、编码错乱、CSV 分隔错误、字段错位 | 两个输出文件 |

这些指标用于形成定量分析，例如“某平台关键结论数更多但证据定位率较低”“某平台 CSV 可解析性影响人工复核”。不得把关键结论数简单等同于质量；结论多但证据弱，仍应在质量维度扣分。

## 十、效率评分，10 分

效率使用 `F:\GitHub\AI_Agent\02_事实核验\测试二时长记录.xlsx` 中 FACTS Grounding 区块的逐题耗时。计时口径为：从发送本题材料和提示词开始，到平台完成规定文件输出为止。

平台总耗时为 9 题耗时之和，单位统一换算为秒。

```text
效率得分 = 10 × sqrt(三家中最短总耗时 ÷ 本平台总耗时)
```

- 最快平台效率得分为 10 分。
- 若某题重跑，应优先使用用户指定的正式轮次；未指定时，使用第一次完整交付且未被废弃的轮次。
- 因网络中断、上传失败、权限弹窗、人工复制文件导致的额外时间，应在审计备注中说明；若计时无法拆分，则保留在总耗时中。
- 效率得分保留两位小数。

## 十一、积分与成本分析

积分用于资源扩展分析，不进入三家主评分排序。当前可量化的成本字段包括 WorkBuddy 积分消耗和 TRAE Work 积分消耗；ChatGPT Work 若无同口径积分记录，则成本项标记为“不适用/未记录”。

每个平台记录以下成本指标：

| 指标 | 计算方法 |
| --- | --- |
| 总积分 | 9 题积分消耗之和 |
| 平均积分 | 总积分 ÷ 有积分记录的题数 |
| 积分标准差 | 逐题积分的标准差 |
| 积分变异系数 | 积分标准差 ÷ 平均积分 |
| 单题积分范围 | 最高单题积分、最低单题积分、最高/最低倍数 |
| 时间-积分相关性 | 逐题耗时与逐题积分的相关系数 |
| 质量-积分相关性 | 逐题质量分与逐题积分的相关系数 |
| 单位资源质量 | 质量分 ÷ 总积分，或每 100 积分质量分 |

解释规则：

- 积分高低可以说明资源消耗和稳定性，不能直接说明答案质量高低。
- 积分波动可能来自任务难度、上下文长度、工具调用、模型路由、重试、平台计费策略等多种因素；没有平台路由日志或固定模型复测时，不得断定“积分波动等于模型切换”。
- 若某平台积分变异系数较高，只能表述为“资源消耗稳定性较弱”或“可能存在动态资源分配”，并说明证据限制。
- 成本分析应与逐题质量、逐题耗时、上下文分层一起交叉解释。

## 十二、缺失、异常与重跑处理

1. 文件缺失：缺少 `grounding回答.md` 或 `grounding证据映射.csv`，该题质量分为 0 分，并记录缺失文件。
2. CSV 异常：CSV 无法解析、列名错乱、字段错位时，不直接整题归零；按受影响范围扣减证据可追溯性、完整性和可复核性，并在备注中说明。
3. MD/CSV 冲突：若报告正文与 CSV 对同一结论的段落、引句或判断不一致，按较低可信度计分。
4. 越界来源：若输出引用外部链接、外部事实或模型常识，相关结论不得计入材料内支持；严重时该题质量分最高不超过 4 分。
5. 重跑结果：只评审用户明确指定为正式结果的轮次；旧结果应进入备份或备注，不与正式轮次混算。
6. 人工干预：仅记录平台运行中断、手动提醒、路径修正等事实；不得因为人工干预本身给质量加分。若人工干预改变了答案内容，应在审计报告中说明该轮结果不再是纯自动产出。

## 十三、扣分记录格式

所有扣分必须逐项记录，不能只写总评。评分明细至少包含以下字段：

```text
平台,测试编号,上下文分层,评分维度,满分,得分,扣分,扣分原因,使用文件,复核备注
```

其中 `使用文件` 应明确写出本次判断依赖的是：

```text
任务说明.md
context_document.md
grounding回答.md
grounding证据映射.csv
测试二时长记录.xlsx
```

若扣分依据来自具体段落或 CSV 行，应在 `复核备注` 中标明段落编号、结论编号或行号。

## 十四、综合得分与并列规则

```text
质量分 = 9 题质量分之和
主评分 = 质量分 + 效率得分
```

主评分保留两位小数。若出现并列，依次比较：

1. 质量分。
2. 材料内事实可靠性总分。
3. 回答完整性与任务覆盖总分。
4. 证据可追溯性总分。
5. 效率得分。

最终报告应同时给出主评分、逐题质量明细、结构量化指标、耗时分析和积分分析。结论必须区分“质量差异”“效率差异”“资源消耗差异”，不得把三者混为一谈。
