# 测试一评分规则细化

## 一、评分思路

测试一是开放式行业研究任务，不能只按“文字好不好看”评分。建议把质量拆成五类：事实可靠性、研究完整性、来源与引用、工作流交付、分析观点。效率单独记录，不直接并入质量分。

## 二、质量总分

| 一级维度 | 权重 | 核心问题 | 评分方法 |
|---|---:|---|---|
| 事实可靠性 | 35% | 它说出来的关键事实是否正确？ | 抽检关键事实，按正确/部分正确/错误/无法判断计分 |
| 研究完整性 | 20% | 它有没有覆盖应覆盖的模型、字段和演进环节？ | 对照模型清单和字段清单打覆盖分 |
| 来源与引用 | 20% | 来源是否真实、有效、能支持正文结论？ | 抽查引用链接、来源类型和支持关系 |
| 工作流交付 | 10% | 是否按要求交付数据库、事实清单、备忘录、PPT大纲、风险提示？ | 检查文件完整性、格式可复核性、事实编号可追溯性 |
| 分析观点 | 15% | 是否能从事实中提炼策略判断，而不是堆资料？ | 按固定 Rubric 人工评分 |

## 三、事实可靠性评分

从每个平台的 `关键事实核验清单.md` 和 `智谱模型迭代数据库.md` 中抽取 30 条关键事实进行复核。

建议分层抽取：

| 事实类别 | 抽取数量 |
|---|---:|
| 发布时间 | 5 |
| 参数口径 | 5 |
| 上下文长度 | 4 |
| 开源/开放方式 | 4 |
| Benchmark/榜单/排名 | 6 |
| 产品/API/价格/生态 | 3 |
| 能力升级 | 3 |
| 合计 | 30 |

每条事实计分：

| 判断 | 分值 | 说明 |
|---|---:|---|
| 正确 | 1 | 来源直接支持，口径清楚 |
| 部分正确 | 0.5 | 方向正确，但日期、口径、版本或表述不完整 |
| 错误 | 0 | 与可靠来源冲突，或把未披露写成确定事实 |
| 无法判断 | 不计入准确率分母 | 已明确标为未确认或来源不足 |

事实可靠性得分 = 已复核事实得分 / 可判断事实数量 * 100。

## 四、研究完整性评分

建议检查两个覆盖率。

### 1. 模型覆盖率

核心模型清单：

| 必须覆盖项 | 说明 |
|---|---|
| GLM / GLM-10B | 早期架构与技术底座 |
| GLM-130B | 千亿双语基座与开源影响 |
| ChatGLM / ChatGLM-6B | 对话产品化与开源生态起点 |
| ChatGLM2 / ChatGLM3 | 长上下文、效率、工具调用与 Agent 原型 |
| GLM-4 | 闭源旗舰、长上下文、All Tools |
| GLM-4V / GLM-4V-9B | 视觉理解与多模态路线 |
| GLM-4-9B / 32B | 开源中小模型路线 |
| GLM-4.5 / GLM-4.5-Air | MoE、推理、编码、Agent 原生融合 |
| GLM-4.5V | 视觉推理与 GUI/文档能力 |
| GLM-4.6 / GLM-4.7 | 后续编码、Agent、上下文升级 |
| GLM-5 / GLM-5.2 | 最新长程任务与工程 Agent 路线 |
| AutoGLM / 相关 Agent 产品 | 从聊天到执行任务的产品化路线 |

模型覆盖率 = 正确覆盖项数量 / 12。

### 2. 字段覆盖率

每个关键模型至少应覆盖：发布时间、参数口径、上下文长度、模态能力、开源/开放方式、主要能力升级、代表性评测、应用入口、来源、未确认项。

字段覆盖率 = 正确填写字段数量 / 应填写字段数量。

## 五、来源与引用评分

每个平台抽查 20 条引用，优先抽查涉及参数、日期、Benchmark、价格、排名的引用。

| 指标 | 计算方式 |
|---|---|
| 引用有效率 | 能打开或能定位到原来源的引用数 / 抽查引用数 |
| 引用支持率 | 来源确实支持对应结论的引用数 / 抽查引用数 |
| 一手来源比例 | 官方、论文、技术报告、GitHub、模型卡数量 / 抽查引用数 |
| 冲突处理得分 | 发现冲突并正确标注的数量 / 应标注冲突数量 |

## 六、工作流交付评分

| 项目 | 分值 |
|---|---:|
| 5 个指定文件全部交付 | 20 |
| 数据库表头完整、可复制复核 | 20 |
| 事实核验清单不少于 40 条 | 20 |
| PPT 大纲 8-10 页，且引用事实编号 | 20 |
| 未确认信息和风险提示单独列出 | 20 |

## 七、分析观点评分

| 指标 | 0 分 | 3 分 | 5 分 |
|---|---|---|---|
| 模型策略判断 | 无判断或空泛 | 有方向判断但证据弱 | 能从时间线、开源/闭源、Agent 化路线提炼策略 |
| 事实与推断区分 | 混在一起 | 部分区分 | 明确标注哪些是事实、哪些是推断 |
| 竞争位置判断 | 直接套用宣传语 | 有对比但口径一般 | 能区分官方自评、第三方榜单、市场判断 |
| 后续跟踪框架 | 没有或泛泛而谈 | 有维度但不可执行 | 有指标、来源、频率和观察阈值 |

分析观点得分 = 四项合计 / 20 * 100。

## 八、效率指标

效率不进入质量总分，单独展示。

| 平台 | 总耗时 | 总耗时秒 | 备注 |
|---|---:|---:|---|
| ChatGPT Work | 7分29秒03 | 449.03 | 速度中等 |
| WorkBuddy | 14分53秒74 | 893.74 | 最慢，但输出覆盖最广 |
| TRAE Work | 4分45秒44 | 285.44 | 最快，但输出较压缩 |

最终报告建议用二维表达：

- 横轴：质量总分；
- 纵轴：总耗时或人工修正时间；
- 单独标注干预次数。
