# L3 摩擦对比层：任务包冻结说明

冻结版本：V1.1（2026-08-06 更新；依据《00_设计/腾讯生态测试优化方案_v2.md》L3 层设计）

> 本层回答 RQ4 的核心问题：WorkBuddy + 腾讯生态闭环,相比传统人工工作流,到底减少了多少摩擦?本层不测「谁做得更好」,只测「哪条路径的动作更少、切换更少、更快」。

## 一、对照任务（固定）

选取与 L2 交付类任务同构的任务作为对照对象：

> 任务目标：将《HERB-01 ProposalForce 项目审阅与推进报告》制作成 PPT 并完成分发（邮件）。

**执行方式：记录型对比（V1.1 调整，用户确认）**。不再单独跑 B 路径人工实测，直接引用 L2-R3 的实测失败数据作为 A 路径证据，与人工基线估算对比。

### 调整背景（V1.1）

- L2-R3（PPT+QQ 邮箱分发）已于 2026-08-06 实测失败终止：执行约 60 分钟、4 次人工干预、邮件未发出，失败记录见 `L2_真实闭环层\03_输出记录\R3\DeepSeek_V4_Flash\R3_执行失败记录_任务终止.md`；
- 用户判断：**「R3 完全证明了 agent 在发邮件方面，现在不如人」**——A 路径在分发环节已无对照价值，再跑 B 路径人工实测是时间浪费；
- 因此 L3 改为**记录型对比**：A 路径 = R3 实测数据，B 路径 = 人工基线估算（含步骤/切换/耗时区间），对比结论以 R3 失败本身为证据。

## 二、A 路径数据来源（固定引用 L2-R3 实测）

| 指标 | A 路径（WorkBuddy，R3 实测） | 数据来源 |
|---|---|---|
| 操作步骤数 | PPT 生成成功（kdocs aippt）+ 附件压缩 3 轮 + 邮件发送重试 3 轮 + 安装依赖重试 4 次 | R3 失败记录时间线 |
| 软件切换次数 | skill 安装 / kdocs / python-pptx / qq-mail 多通道往返 | 同上 |
| 人工动作数 | 4 次人工干预（提示换方案 ×2、提示卡死 ×1、终止 ×1）+ 1 次发送确认 | 同上 |
| 总耗时 | 约 60 分钟（19:13—20:12），邮件未发出 | 同上 |
| 失败/重试 | 附件传参相关重试 3 轮均失败；任务终止 | 同上 |

## 三、B 路径（人工基线估算）

**不做实测**（用户确认省时间），按行业常识估算并标注区间，口径与 A 路径一致：

| 指标 | B 路径（人工，估算区间） | 估算依据 |
|---|---|---|
| 操作步骤数 | 8–15 步 | 制作 5 页 PPT（模板套用）+ 写邮件 + 附件 + 发送 |
| 软件切换次数 | 2–3 次 | PPT 软件 → 邮箱 →（可选）文件管理器 |
| 人工动作数 | 8–15 步（全部人工） | 同步骤数 |
| 总耗时 | 10–20 分钟 | 熟练办公人员制作 5 页简报 + 邮件发送 |
| 失败/重试 | 通常 0；偶发附件过大时压缩 1 次 | 常识 |

> 估算必须标注为「估算区间，非实测」，报告中不得写成实测数据；结论仅用于量级对比。

## 四、对比结论（固定表述方向，V1.1）

1. **时间量级差异 ≥3 倍**：A 路径 60 分钟未完成 vs B 路径 10–20 分钟完成 → 符合「≥2 倍差异」结论纪律，可下结论；
2. **完成状态差异**：A 路径失败（0 交付）vs B 路径成功（完整交付）→ 该差异无需统计学支撑，属任务级事实；
3. **人工介入**：A 路径需 4 次干预 vs B 路径 0 干预；
4. **核心结论（用户确认）**：**「WorkBuddy 在『制作 PPT + 发送邮件』环节，当前效率与可靠性均不如人」**——生态覆盖面广，但分发环节摩擦为负，个人用户在此场景无付费价值。

## 五、对比指标与输出格式

对比结果保存至 `L3_摩擦对比层\02_输出\L3摩擦对比结果.md`，固定包含：

- A/B 两路径指标表（A 实测、B 估算区间）；
- 差异量级判定（≥2 倍 / 量级相当）；
- 结论段（引用用户确认的核心结论）；
- 方法学声明（B 为估算区间，非实测；R3 失败数据为实测）。

## 六、固定对象与执行前提

- 样本量：A 路径 1 组实测（R3 已提供）；B 路径 0 组实测（估算）；
- 禁止：将 B 路径估算表述为实测；不同任务混比；结论超出量级纪律。
- 本层不再需要执行实验，仅需将 R3 数据与人工基线整理成对比表——**无需用户额外操作，不跑代码、不跑实验**。
