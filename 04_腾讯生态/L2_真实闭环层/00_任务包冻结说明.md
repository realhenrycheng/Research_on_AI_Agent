# L2 真实闭环层：任务包冻结说明

冻结版本：V1.3（2026-08-06 更新；依据《00_设计/腾讯生态测试优化方案_v2.md》L2 层设计）

> 本层验证「腾讯生态连接不是宣传，而是真的能读写、能沉淀、能分发」。与 L1 不同，本层不测模型推理质量，测的是**生态闭环可用性**。所有任务在 WorkBuddy 对话中由用户下达固定指令执行，用户按本说明的记录规范逐项记录。

## 一、固定对象（执行前必须逐项确认并记录）

| 项目 | 固定规则 |
|---|---|
| 被测平台 | WorkBuddy（本层为平台差异化验证，不参与三家竞品总分） |
| 模型 | **仅 DeepSeek V4 Flash（开启 MAX）**。HY3 已跑 R1 一轮作为参考组（2026-08-06），因效率过低（三阶段约 74 分钟）后续任务全部改用 DS；HY3 结果不参与模型对比，单独归档于 `03_输出记录\R1\Hy3+Max\` |
| 连接器 | R1 用腾讯文档(tencent-docs，已连接)；R2 用 **ima 知识库(ima-mcp，已连接，用户选定，不再二选一)**；R3 用腾讯系 PPT 技能 + QQ 邮箱(qq-mail，已连接)；**R3 扩展：企业微信(wecom)——2026-08-06 实测连接失败（个人账号无企业主体，无法授权），放弃该扩展，如实记录为「入口层未实测」，见变更记录 V1.2**；可选深挖：微云(tencent-weiyun，未连接，需用户授权)备份链路、腾讯会议(tmeet，已连接)能力探查 |
| Skill | R3 使用 tencent-pptx；其余任务如有调整，必须记录 Skill 名称与版本 |
| 输入文件 | 仅使用 L1 已冻结资料包（`L1_能力层_模拟\01_资料包\`），或本层 `01_任务包` 中固化的指令与材料引用；任务包材料不另行复制，统一引用 L1 冻结文件（材料引用清单见 `01_任务包\00_材料清单与引用.md`） |
| 输出路径 | 统一写入 `F:\GitHub\AI_Agent\04_腾讯生态\L2_真实闭环层\03_输出记录\{R?}\{模型}\`，每任务独立子目录，禁止覆盖 |
| 环境前提 | 执行前确认对应连接器处于「已连接」状态；某连接器不可用时改期执行，不硬跑、不降级到本地模拟替代 |
| 平台记录（新增，V1.3） | **连接器实际后端可能与会话暴露的工具不一致**。HY3 R1 实测：`mcp__tencent-docs__*` 工具未暴露，实际可用文档工具为 `mcp__kdocs__*`（金山文档 KDocs 后端，域名 kdocs.cn）。**执行时必须如实记录实际后端与域名**，不得将 kdocs 落点表述为腾讯文档；DS 轮 R1 优先确认 tencent-docs 工具是否暴露，若仍不可用则如实记录平台并评估补充方案 |

## 二、任务包构成（R1—R4，深挖版）

### R1 腾讯文档写回与增量修订闭环（含评论批注与分享链接）

**场景**：交付出口 + 持续维护载体。材料取自 L1 的 HERB 任务链，与 L1 形成「模拟→真实」对照。

**阶段一固定指令（用户原样下发）**：

> 请在腾讯文档中新建在线文档《HERB-01 ProposalForce 项目审阅与推进报告（生态写回测试）》，将本地文件 `L1_能力层_模拟\04_任务输出\{模型目录}\HERB-01_ProposalForce项目审阅与推进报告.md` 的内容完整写入该文档，保留标题层级与表格结构，完成后返回文档链接与写入状态。

> 说明：`{模型目录}` 按当前模型取 `DeepSeek_V4_Flash\HERB+DS` 或 `Hy3\HERB+Hy3`；若两模型均已完成 HERB-01，统一以 DeepSeek_V4_Flash 版本为 R1 输入基准（执行前在记录表中注明所用版本）。

**阶段二固定指令（在阶段一完成后下发）**：

> 请读取腾讯文档《HERB-01 ProposalForce 项目审阅与推进报告（生态写回测试）》的当前内容，结合本地追加材料 `L1_能力层_模拟\01_资料包\HERB_ProposalForce\第二阶段追加材料\01_ProposalForce_第二阶段追加材料.md`，修订报告结论：保留仍然有效的结论，修正已失效的结论，在文末增加「本次变更说明」，并将修订版写回同一腾讯文档（不得新建文档），完成后返回修订说明与文档链接。

**阶段三固定指令（深挖：评论批注 + 分享链接，执行层写操作）**：

> 请在修订后的腾讯文档中，对「待确认事项」一节插入一条批注/评论，内容为「此节需产品负责人人工确认，WorkBuddy 标记为待办」，然后获取该文档的分享链接（可查看权限），返回批注位置与分享链接。

**输出格式**：阶段一、二、三各输出一份《R1闭环执行记录表》，字段见第三节；修订说明需写入腾讯文档文末。

**评分锚点（通过判据，人工核验）**：

| 指标 | 判据 | 判定方式 |
|---|---|---|
| 文档创建成功 | 返回可打开、可分享的文档链接 | 人工点击验证 |
| 写回内容完整 | 与本地源文件逐段比对，段落一致率 100% | 逐段比对计数 |
| 格式保持 | 标题层级、表格、加粗是否保持 | 人工目视，记「保持/丢失/乱码」 |
| 读回正确 | 阶段二读取内容 = 阶段一写入内容 | 比对 |
| 增量修订正确 | 仅改应改处，未变内容保留；变更说明可追溯 | 与 L1 评分结论比对 |
| 评论批注成功 | 批注/评论写入成功、位置正确、可查看 | 人工在文档中查看 |
| 分享链接有效 | 链接可打开、权限设置生效 | 人工点击验证 |
| 记录完整 | 步骤数、人工介入、耗时、积分齐全 | 检查记录表 |

### R2 ima 知识库沉淀与检索闭环（含 URL 导入 + 增量更新 + 检索驱动创作）

**场景**：企业知识库 = 长期记忆载体。用户已选定 **ima**。

**步骤一固定指令（文件入库）**：

> 请在 ima 知识库中新建知识库《WorkBuddy生态测试-知识库闭环》，将本地目录 `L1_能力层_模拟\01_资料包\MuDABench_中文企业资料库分析\q_8b4f852a15496a80` 下的源 PDF 上传入库，完成后返回入库结果与知识库链接。

**步骤二固定指令（URL 导入，深挖：网页入口）**：

> 请将以下网页 [用户指定一个公开网页，如 WorkBuddy 官方文档页或指定研究报告页面] 以链接形式导入同一 ima 知识库，完成后返回导入结果。若该网页无法导入，明确说明原因并记录为失败项。

**步骤三固定指令（增量更新，深挖：版本演进）**：

> 请将本地文件 `L1_能力层_模拟\04_任务输出\DeepSeek_V4_Flash\HERB+DS\HERB-01_ProposalForce项目审阅与推进报告.md` 与修订版 `HERB-02_ProposalForce项目审阅与推进报告_修订版.md` 一并上传到同一 ima 知识库（分属两个文档），完成后返回入库结果，并说明知识库中如何区分报告初版与修订版。

**步骤四固定指令（检索驱动创作，深挖：知识库→文档信息流）**：

> 请仅基于 ima 知识库《WorkBuddy生态测试-知识库闭环》中的文档，回答：「根据库内资料，2022 年资本充足率最高的三家银行是哪些？各自的资本充足率与来源文档是什么？」回答须引用库内文档；随后基于该检索结果生成一段 200 字以内的摘要，供后续写入腾讯文档。

**输出格式**：各步骤入库/导入/检索结果、引用文档名列表、200 字摘要。

**评分锚点**：

| 指标 | 判据 |
|---|---|
| 文件入库成功率 | 上传文档全部入库成功，失败项可修复且记录 |
| URL 导入 | 网页导入成功或明确说明失败原因（失败不扣分，记录即可） |
| 增量更新 | 初版与修订版可区分、均可检索 |
| 检索命中 | 回答基于库内文档，未引用库外内容 |
| 引用可定位 | 引用指向库内正确文档与位置 |
| 拒答正确 | 涉及未入库材料时明确说明，不编造 |
| 摘要可用 | 摘要内容与库内事实一致、可直接复用 |

### R3 交付分发闭环（腾讯系 PPT + QQ 邮箱 + 可选微云备份）

**场景**：生成 → 分发一步到位。

**主任务固定指令**：

> 请基于本地报告 `L1_能力层_模拟\04_任务输出\DeepSeek_V4_Flash\HERB+DS\HERB-01_ProposalForce项目审阅与推进报告.md` 生成 5 页《ProposalForce 项目简报》PPT；完成后，将 PPT 文件与报告一起作为附件，通过 QQ 邮箱发送到 [用户指定邮箱]，主题为「WorkBuddy 生态测试：ProposalForce 项目简报」，并在对话中确认发送状态。

**企业微信扩展：已放弃（2026-08-06 实测连接失败）**。失败原因：个人账号无企业主体（无公司/团队），无法完成 wecom 连接器授权。**该失败如实记录为「入口层（企业微信）未实测」**，并作为研究发现写入 04 模块结论与最终报告 6.2 连接深度表——个人用户无法使用企微连接，是 WorkBuddy 面向个人用户时生态深度的真实边界（佐证 H5 用户分层假设）。

**可选扩展 A（微云备份，需用户先授权 tencent-weiyun）**：

> 请将《ProposalForce 项目简报》PPT 与报告文件上传到微云（或新建文件夹「WorkBuddy生态测试」），完成后返回上传结果与链接。

**可选扩展 B（腾讯会议能力探查，已连接，零成本）**：

> 请查看腾讯会议连接器可用的能力范围（如是否能查询会议记录、创建会议），并简要说明在本测试环境中哪些能力可用于办公场景；如用户有真实会议记录，可将一份会议纪要文本导入 ima 知识库作为后续材料。

**输出格式**：PPT 文件路径、邮件发送状态、附件清单、微云上传状态（如执行）、腾讯会议能力探查说明（如执行）。

**评分锚点**：PPT 生成成功且可打开；PPT 内容与报告关键结论一致；邮件发送成功；微云上传成功（如执行）；全程步骤与人工介入已记录；企微失败已如实记录。

### R4 本地 Office 文件检查（简化版）

**场景**：验证本地 Office 文件的读取与检查能力，不做复杂修改。

**固定指令**：

> 请用本地 Office 编辑能力打开本地文件 [指定 docx/xlsx 路径]，检查文件是否可正常打开、内容是否完整可读，并简要说明文件包含哪些内容（如表格标题、数据范围），不需要修改任何内容，完成后返回检查结果。

**评分锚点**：文件可正常打开；内容可读且描述准确；未发生意外修改。

## 四、变更管理

- 任何修改(指令文本、任务包、输出路径、判据)必须先升版本号并记入变更记录;
- 指令文本必须**原样**下发,不得在对话中口头改动措辞;
- 未变更时,结果可跨日期复现;变更后必须另记版本,禁止与新版本混比;
- 模型对比仅限 HY3 与 DS（均 MAX）；如需引入其他配置，另建扩展观察组。
