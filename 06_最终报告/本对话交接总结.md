# AI Agent 竞品测试项目交接总结

## 一、项目基本信息

项目路径：

```text
F:\GitHub\AI_Agent
```

项目面向中文读者，原则上所有自建文件、说明文档、提示词、评分规则、分析报告、运行记录均使用中文；下载的原始 Benchmark 文件可以保留英文。

项目目标是围绕 WorkBuddy、ChatGPT Work、TRAE Work 三类 agent，做多维度竞品评估，重点关注：

- 研究型任务能力；
- 事实核验能力；
- 办公成果编辑能力；
- 运行效率；
- 成本或积分消耗；
- 输出结构与人工复核便利性；
- 不同模型配置对平台表现的影响。

## 二、已确定的重要原则

### 1. 竞品范围

核心测试平台：

- WorkBuddy；
- ChatGPT Work；
- TRAE Work。

Codex 不纳入核心竞品实测，因为更接近软件开发 Agent 类别；Manus 不纳入核心实测。

### 2. 文件与目录原则

项目目录已汉化，除下载的英文源文件外，其他目录和文件尽量使用中文命名。

曾经因为 GitHub 100MB 限制，已设置不上传：

```text
F:\GitHub\AI_Agent\03_办公成果编辑\SpreadsheetBench2数据
```

其他内容可以正常 push。

### 3. 运行记录原则

`运行记录.csv` 不再记录开始时间、结束时间和成本额度使用量字段，而是用“总耗时”替代开始结束时间。成本、积分、上下文等如果有记录，作为补充字段或专门分析字段使用。

测试过程中用户手动记录：

- 总耗时；
- 必要时记录逐题时长；
- WorkBuddy/TRAE 的积分消耗；
- 上下文使用量；
- 模型参数或模式；
- 是否开启 MAX 模式；
- 输出保存路径；
- 是否重跑。

### 4. 评分原则

质量优先，效率和成本量化但保持低权重。不能只因为积分波动就断定平台切换了模型，只能表述为成本可预测性、资源调度稳定性或模型配置敏感性问题。

评分必须定性与定量结合，且说明：

- 每个维度如何判分；
- 使用哪个输出文件；
- 缺失、异常、重跑如何处理；
- 公式如何计算；
- 扣分依据如何记录；
- 证据如何复核。

## 六、已经形成的整体竞品判断

### ChatGPT Work

优势：

- 研究型任务质量稳定；
- 事实核验中耗时较短；
- 引用证据相对保守；
- 报告成品化能力强。

不足：

- 速度不是所有任务中最快；
- Factcheck 深层声明拆解不占优；
- FACTS 中复杂约束识别出现过明显错误；
- 办公成果编辑测试中存在图表失败问题。

适合定位：

```text
稳定型研究与核验助手，适合生成报告初稿和进行保守证据核验。
```

### WorkBuddy

优势：

- 研究覆盖面强；
- 办公成果编辑表现最好；
- 强模型或 MAX 模式下测试一质量明显提升；
- 长上下文任务覆盖能力较强。

不足：

- HY3 基线版来源质量弱；
- 对底层模型和配置依赖很强；
- 积分消耗和波动较大；
- 成本可预测性弱；
- 偶发 CSV、证据映射、结构问题。

适合定位：

```text
高上限但强依赖模型配置的平台，适合质量优先、可接受复核和成本波动的场景。
```

### TRAE Work

优势：

- 测试一速度最快；
- FACTS Grounding 表现最佳；
- 成本和积分稳定性优于 WorkBuddy；
- 来源与引用结构较好。

不足：

- 测试一研究完整性和分析深度不足；
- Factcheck 基础可核验性判断失分；
- FACTS 长上下文中存在段落编号虚构风险；
- 办公编辑中出现过文件不可用问题。

适合定位：

```text
速度和成本效率较强的平台，适合快速调研、快速 grounding 和资源可控场景。
```
