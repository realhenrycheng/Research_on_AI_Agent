## 三、章节结构与素材映射（05 产出 → 最终报告第 17-21 节）

### 3.1 用户价值（13.1）——五类用户 × 实测证据

| 用户类型 | 核心判断 | 证据来源 |
|---|---|---|
| 个人知识工作者 | 仅在"资料检索/知识库"环节有价值（R2 正 ROI）；分发环节负 ROI | 04：R2 20分钟可用 vs R3 60分钟失败 |
| 技术型研究员 | 增量价值有限（H3 假设），有编程能力者可用脚本替代 | 测试二 FACTS、设计稿 H3 |
| 非技术型研究员 | 低门槛价值明显，但需人工复核闭环 | 04：MuDABench 口径分歧、L1 复核定位 |
| 中小团队 | 知识库沉淀 + 权限管理是核心卖点 | 04：ima 知识库 R2；13.2 企业席位 |
| 大型企业 | 生态入口 + 安全部署 + 审计是付费关键 | 04：企微入口层企业专属；13.4 安全部署 |

### 3.2 收入来源（13.2）——基于定价搜集 + Credits 实测

- 个人订阅 / 企业席位：定价页搜集（待 WebSearch）；
- Credits 消耗：**已有实测数据**——测试二 WorkBuddy 积分 323.74（Factcheck）/ 174.96（FACTS），变异系数 66-67%（成本可预测性弱）；
- 专有云 / 私有化 / 云服务调用：官方资料搜集 + 商业推断；
- **关键测算**：结合 Credits 价格 × 单次任务积分 × 月频 → 单用户月成本（可给出区间，标注为估算）。

### 3.4 护城河判断（13.4）——八维度

| 维度 | 判断 | 证据 |
|---|---|---|
| 模型壁垒 | 弱（可用任意模型，无独占） | 用户实测接 DeepSeek API 即可 |
| 产品体验 | 中等（Agent 无止损机制是短板） | 04：R3 4 次人工干预 |
| 工作流沉淀 | 强（Skills/MEMORY/记忆体系） | 项目全流程体验 |
| 数据与知识库 | 强（ima/乐享） | 04：R2 全链路 |
| 腾讯生态 | 广而不深（覆盖面广、稳定性不均） | 04 整体反馈 |
| 企业客户关系 | 潜在强（依托腾讯企业服务渠道） | 推断 |
| 安全与部署 | 待验证（企业版未实测） | 缺证据，标注 |
| 用户迁移成本 | 中等（连接器绑定 vs 模型可替换） | 推断 |

### 3.5 风险（13.5）——与实验结论逐条挂钩

| 设计稿风险 | 实验佐证 |
|---|---|
| 通用模型能力追平 | ✅ 04：模型可替换（DS API），无模型护城河 |
| Agent 可靠性不足 | ✅ 04：R3 失败、通道崩溃、无止损；测试二 CSV 转义/编号错误 |
| Credits 成本过高 | ✅ 测试二：积分波动 66-67% 变异系数 |
| 企业数据安全 | 未实测，标注待验证 |

| 生态外竞争力不足 | ✅ 04：企微入口个人不可达；分发环节不如人 |
| 功能广但专业深度不足 | ✅ MuDABench 口径分歧；需行业模板 |

## 四、「研究助手构想」——畅想未来：现有优势分析 + 优化思路

**定位**（按设计稿第十四节）：不默认 WorkBuddy 已是 Research Copilot；基于实验暴露的缺陷反向提出理想产品；给出「现状 → 差距 → 优化路径」三段式。

### 4.1 现有优势分析（实验已验证的，不是畅想）

1. **材料消化与证据定位能力强**：HERB DS 满分、MuDABench 证据可复核性 6/6 满分（15/15）；
2. **知识库沉淀与检索真实可用**：ima 入库/URL/增量/检索/引用/拒答全链路打通（R2）；
3. **文档写回与增量修订链路成立**：写回/读回/修订/批注/分享（R1，平台偏差需注明）；
4. **强模型配置下接近第一梯队**：测试一 Auto+MAX 91.25 / DS+MAX 90.00；
5. **办公成果编辑表现最好**：测试三约 92.10（三家最高）。

### 4.2 优化思路（按实验暴露的缺陷反向设计，每条对应一个实测缺陷）

| 实验缺陷 | 优化思路（Research Copilot 能力） |
|---|---|
| Agent 无止损/反思（R3 重试 4 轮） | 设计「失败检测-止损-上报」机制：N 次重试失败自动暂停并给用户替代方案 |
| 附件/参数体量无边界预检（R3 base64 卡死） | 工具调用前做参数体量预检，超限自动切换替代通道（如微云链接） |
| Skill 依赖装不上（tencent-pptx） | Skill 依赖预置/离线包化；连接器能力探测与自动降级 |
| 知识库解析进度导致静默错误（R2 前三错误） | 检索前检查解析覆盖率，未解析文档明确提示"结论不完整" |
| 口径敏感任务需要人工复核（MuDABench 4 处分歧） | 行业模板 + 口径预设（固定研究对象、统一字段、来源规范） |
| 分发环节不如人（R3/L3） | 先做"生成+链接分发"而非附件分发；微云/腾讯文档链接替代邮件附件 |
| 需全程盯守（4 次干预） | 人工复核点机制化：仅在关键节点要求确认，而非全程监控 |
| 无行业深度（广而不深） | 垂直行业 Agent：行业模板、估值框架、来源白名单、观点版本管理 |

### 4.3 理想能力清单（设计稿第十四节 → 可行性标注）

| 能力 | 可行性 | 依据 |
|---|---|---|
| 固定研究对象 | 高（现在即可） | 记忆体系已具备 |
| 自动监控官方来源 | 中（需定时任务+来源白名单） | 定时任务能力存在，未实测 |
| 长期维护数据库 | 高 | ima/表格闭环已验证 |
| 自动识别信息变化 | 中 | R1 增量修订已验证雏形 |
| 观点版本管理 | 中 | 知识库版本区分已验证（R2 步骤三） |
| 报告PPT增量更新 | 中低 | R1 修订可用；PPT 分发环节失败 |
| 事实核验 Agent | 中 | 测试二 FACTS 表现好但需复核 |
| 数据处理 Agent | 高 | 测试三办公编辑最好 |
| 行业模板与估值框架 | 高（需人工配置） | Skill 体系可承载 |
| 权限引用审计 | 中（企业版待验证） | 未实测 |

### 4.4 终极战略判断（回应设计稿）

> 通用 Agent 不足以服务专业研究 → 需要**垂直行业 Agent 平台**。WorkBuddy 的合理演进路径：通用办公 Agent（现状）→ 腾讯企业服务 AI 入口（数据层已通）→ 可承载垂直专业 Agent 的平台（行业模板+复核机制）→ 而非单纯的桌面 Agent 操作层。理由：模型无壁垒（可替换）、连接器有壁垒但不稳（需生态深耕）、知识库+模板+复核闭环才是可沉淀的护城河。
