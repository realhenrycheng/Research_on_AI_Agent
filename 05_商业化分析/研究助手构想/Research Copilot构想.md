# Research Copilot 构想（畅想未来）

> 版本：V1.0（2026-08-06）
> 依据：设计稿第十四节《Research Copilot 构想》+ 本项目全部实验证据
> 定位：不默认 WorkBuddy 已是 Research Copilot；基于实验暴露的缺陷，反向提出理想产品。本章为畅想部分，由「现有优势分析（实证）→ 优化思路（按缺陷反向设计）→ 理想能力清单（可行性标注）→ 战略判断」四段构成。

## 一、现有优势分析（实证验证，非畅想）

以下五项均有本项目实测数据支撑，是 Research Copilot 的起点：

| 优势 | 实测证据 |
|---|---|
| 材料消化与证据定位能力强 | HERB DS 满分（100/100）；MuDABench 证据可复核性 6/6 满分（15/15） |
| 知识库沉淀与检索真实可用 | ima 入库/URL 导入/增量更新/检索/引用/拒答/摘要全链路打通（R2，7/7 判据） |
| 文档写回与增量修订链路成立 | 写回/读回/修订/批注/分享（R1，8/8 判据，平台偏差需注明） |
| 强模型配置下接近第一梯队 | 测试一 Auto+MAX 91.25 / DS+MAX 90.00（对比 HY3 基线 83.68） |
| 办公成果编辑表现最好 | 测试三约 92.10（三家竞品中最高） |

## 二、优化思路（按实验缺陷反向设计）

每条优化对应一个实测缺陷——这是"从失败中设计理想产品"：

| 实测缺陷 | 优化思路（Research Copilot 能力） | 优先级 |
|---|---|---|
| Agent 无止损/反思（R3 依赖重试 4 轮、附件重试 3 轮） | 「失败检测-止损-上报」机制：N 次重试失败自动暂停并给用户替代方案 | P0 |
| 附件/参数体量无边界预检（R3 base64 卡死） | 工具调用前参数体量预检，超限自动切换替代通道（如微云链接） | P0 |
| Skill 依赖装不上（tencent-pptx 本地运行时无法安装） | Skill 依赖预置/离线包化；连接器能力探测与自动降级 | P0 |
| 知识库解析进度导致静默错误（R2 前三银行错误：工行/农行未解析） | 检索前检查解析覆盖率，未解析文档明确提示"结论不完整" | P1 |
| 口径敏感任务需人工复核（MuDABench 4 处分歧） | 行业模板 + 口径预设（固定研究对象、统一字段、来源规范） | P1 |
| 分发环节不如人（R3/L3：60 分钟 vs 人工 10-20 分钟） | 先做"生成+链接分发"而非附件分发；微云/腾讯文档链接替代邮件附件 | P1 |
| 需全程盯守（R3 4 次人工干预） | 人工复核点机制化：仅在关键节点要求确认，而非全程监控 | P1 |
| 无行业深度（广而不深） | 垂直行业 Agent：行业模板、估值框架、来源白名单、观点版本管理 | P2 |

## 四、战略判断（回应设计稿终极追问）

> **通用 Agent 是否足以服务专业研究？**

**结论：不足以。** 依据：
- MuDABench 四题口径分歧证明：通用模型缺少行业模板/口径预设时，即便证据充分也会给出与标准答案不一致的结论（71.50 vs HERB 满分 100）；
- 通用 Agent 的"暴露不确定性"行为可复核，但不等于结论正确——需要行业规则约束。

> **WorkBuddy 会成为什么？**

**合理演进路径**：
```
通用办公 Agent（现状）
   ↓ 连接器稳定性修复 + 复核点机制化
腾讯企业服务 AI 入口（数据层/执行层已通，入口层待企业环境验证）
   ↓ 行业模板 + 垂直技能
可承载垂直专业 Agent 的平台（Research Copilot 落地形态）
```

**不做**的方向：单纯的桌面 Agent 操作层（与连接器生态价值冲突）。

**理由（护城河逻辑）**：
1. 模型无壁垒——本项目全程用 DeepSeek API 即可运行，模型可替换；
2. 连接器有壁垒但不稳——腾讯生态连接矩阵广，但稳定性是短板（04 实测）；
3. **知识库 + 行业模板 + 复核闭环才是可沉淀的护城河**——三者都依赖长期使用积累，构成迁移成本。

## 五、对最终报告的意义

- 本章是"畅想未来"部分，但每一处优化都有实测缺陷对应，避免空谈；
